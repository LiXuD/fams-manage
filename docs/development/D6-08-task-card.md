## D6-08A 首个实现边界

持久任务只负责调度与恢复；资产、编号和审批仍由既有业务所有者控制。采用 MySQL，不新增 Redis、MQ 或通用流程引擎。

| 操作 | 最小契约 | 事务与恢复约束 |
|---|---|---|
| 提交 | 任务种类、业务引用、发起账号、请求键、请求摘要 | 同一账号/种类/请求键返回原任务；内容变化拒绝；任务与提交方业务写入共用事务 |
| 领取 | 工作器标识、租约期限；返回任务 ID、执行代次 | 当前可执行任务加锁领取；执行代次递增，保存租约；多个工作器不得同时取得同一代次 |
| 续约 | 任务 ID、工作器、代次 | 仅当前有效租约续约；过期、换代或终态拒绝 |
| 完成 | 任务 ID、工作器、代次、结果引用 | 锁定并确认当前代次与租约；业务副作用和终态一起提交，陈旧执行者不能写回 |
| 失败 | 同上，稳定错误码与可重试性 | 保存尝试次数、错误与下一执行时间；可重试任务退避，永久失败保留任务和原因 |
| 恢复 | 到期 RUNNING 任务 | 租约过期后允许新代次领取；不凭内存或进程 PID 判断业务是否已提交 |

拟用状态：QUEUED、RUNNING、RETRY_WAIT、SUCCEEDED、FAILED；状态迁移由服务端控制。业务处理不跨租约检查单独提交；重试的业务身份固定为任务 ID 和业务引用，不用执行代次作为新的业务请求键。

## 文件与接口所有权

- 预计新增 `com.fams.job` 模块及向前 Flyway 迁移；迁移编号在实际编码时按当前仓库分配，不提前占用编号。
- 内部任务端口先供导入应用服务使用；不提前开放通用管理/执行 REST 接口。
- 导入 HTTP 契约在 D6-08B 中按模板→映射→预检→确认→任务/结果补齐，再生成 Java/TypeScript。现有 identity-imports 是组织/人员原子导入，不作为资产后台导入入口。
- 权限来源于当前业务角色和范围；任务执行时重新校验发起账号和业务事实，不把提交时授权永久缓存为执行权。
- 任务内容和失败记录不保存令牌、密码、手机号全集或原始文件路径；外部可见结果必须重新按业务关系授权。

## 必需定向验证

1. 真实 MySQL 同键并发提交：一份任务；不同内容冲突。
2. 两个工作器领取：一份当前租约；续约及执行代次正确。
3. 租约过期后重新领取，旧代次的续约/完成/失败写回均拒绝。
4. 业务写入或任务完成失败整体回滚；重试只产生一次业务副作用。
5. 独有进程在领取后退出，租约到期由新进程恢复；已完成任务不重新执行。
6. 可重试失败遵守下一执行时间，永久失败留痕；任务与业务权限撤销后拒绝执行。

定向用例先执行；候选稳定后运行 `scripts/verify-product-development.py`，不为每个小提交重跑历史治理和提交 SHA 审计。正式 QA 和共享/生产迁移另行报告。
