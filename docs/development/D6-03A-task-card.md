# D6-03A task card — 本地统一检查

## 任务身份与目标

- **ID：** D6-03A 本地统一检查。
- **目标：** 在 D6-02 已验证的契约、运行组合和首批设计包上，建立可重复的本地 Compose 环境与单一质量入口，使 G1 业务编码从第一笔提交起受到明确、可失败的静态、架构、覆盖率、依赖、密钥、契约漂移和指标暴露规则约束。
- **状态：** `IN_PROGRESS`（2026-09-15）。
- **分支 / 基线：** `feat/D6-03A-local-quality-gate`；`5676bd9823e27ef65988568acd940a7532ab82b7`。
- **前置条件：** D6-01A、D6-02A、D6-02B、D6-02C 均为 `DEV_VERIFIED`；D6-01B 不阻塞本地任务。
- **规模：** M；只交付本地开发环境与质量门禁，不实现业务功能。

## 已批准范围

1. 建立项目级 Compose：复用 D6-02B 已冻结的 MySQL 8.4.11 摘要，提供健康检查、隔离名称、持久卷、明确端口和可重复启动/销毁入口；应用只承载现有契约/兼容性探针。
2. 为现有 Java 21 后端固定 Checkstyle、SpotBugs、ArchUnit 与 JaCoCo 版本和规则；禁止模块循环、跨模块 Mapper 访问和 Controller 事务边界，并为规则建立可证明会失败的负例。
3. 为当前共享 TypeScript 及后续 PC、原生微信小程序源目录固定 ESLint 与 TypeScript 检查；不存在的产品目录不冒充已构建，新增目录后必须自动纳入。
4. 固定依赖、密钥、生成产物和契约漂移检查的实际工具版本、作用范围及失败等级；已有 D6-01A、D6-02A/B/C 门禁必须保留。
5. 接入 Actuator/Micrometer；指标只在本地 Compose 的回环绑定管理端口暴露，业务端口不得公开指标，健康与指标边界需由真实 HTTP 断言证明。
6. 先测量当前有效源码的行/分支覆盖率，再冻结不高于实测值的初始阻断阈值；生成代码、配置类或其他排除项必须逐项说明，不能用覆盖率代替权限、状态、事务、恢复和幂等用例。

## 明确排除

- 不创建登录、基础资料、资产或入库业务实现，不创建 PC 页面或小程序页面。
- 不创建产品表或伪造产品迁移通过；`db/migration/product` 与 D6-02B 探针迁移继续隔离，未来共享迁移只允许前向追加。
- 不配置远端 GitHub Actions、分支保护或 `required-ci`；这些属于 D6-03B，并受 D6-01B 外部权限约束。
- 不把本地 Compose、静态工具或探针 HTTP 结果写成 QA、生产或业务验收通过。

## 实施与验证顺序

1. 为统一验证器的必需文件、固定版本、失败传播、清理和负例行为先建立可复现 RED。
2. 以最小配置接入各工具，逐项取得 GREEN；任何不兼容都记录证据后再选择等价替代，不静默删项。
3. 运行 JaCoCo 报告并记录当前源码分母、生成代码排除及实测行/分支覆盖率，再确定初始阈值。
4. 在干净 Compose 项目中启动 MySQL 与现有后端，验证迁移、健康、受限指标、重启和同卷恢复，最后精确清理本任务容器、网络和卷。
5. 从统一入口复跑 D6-01A 与 D6-02A/B/C 保留门禁、Java/TypeScript 质量检查、依赖/密钥/产物检查和 `git diff --check`。

## 基线证据

- 新工作树首次运行 `scripts/verify-d6-02c.py` 时，D6-02A 保留门禁因 `tools/git/node_modules/.bin/commitlint` 不存在而退出 1；这是新工作树缺少锁定开发依赖，不是产品逻辑失败。
- 执行根目录及 `tools/git` 的锁文件安装后，同一完整入口在固定 Java 21、Node 24.18.0、npm 11.16.0 环境退出 0：81 个 D6-02C 单元测试、102 个 operation / 162 个示例、Java 163 / TypeScript 159 个生成文件、D6-02A/B 保留门禁及差异检查全部通过，生成目录已清理。

## 数据、回滚与恢复边界

- Compose 只使用任务专属项目名、容器、网络和卷；清理目标必须精确，不操作其他 Docker 资源。
- D6-03A 不发布产品迁移，因此没有产品数据变更；探针库可由 Compose 重建，持久卷恢复只证明开发环境重启路径。
- 未共享分支上的配置按功能提交逆序回退；已冻结的 D6-02B 版本和迁移文件不得被改写。
- 远端 CI、真实业务权限/事务、备份恢复演练、QA 和生产均保持未验证。

## 关闭条件

1. 全部候选工具版本、规则、范围、排除依据、失败等级和实测覆盖率阈值记录在任务产物中。
2. 统一入口在干净环境退出 0；至少一个故意违反 Java 静态/架构规则和一个违反 TypeScript 规则的临时负例被拒绝，随后清除。
3. Compose 首次启动、重复启动、应用/数据库重启、迁移和受限指标 HTTP 检查通过，且任务资源精确清理。
4. D6-01A 与 D6-02A/B/C 保留门禁全部通过；不存在跳过、取消或未运行被汇总成成功。
5. 非实施者完成任务级规格与质量复核；控制器对 reviewed HEAD 完整复跑后才可写 `DEV_VERIFIED`。
