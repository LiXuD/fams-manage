## 3. 六条“公理证伪”的裁决

| 编号 | 裁决 | 理由及处理 |
|---|---|---|
| AX-A1 单点决策不充分 | 不采纳其推导 | 高价值设备损失的风险存在，但没有证据说明本企业需要特定价值阈值或三方分离；V1 明确不采原值、允许兼岗，且用户明确不要第二名复核。风险存在不能直接推导必须新增层级。维持单管理员决定，完善已有资产、数量和处置凭证核对；不宣称能消除串通。 |
| AX-A2 独占导致不可用 | 部分采纳 | 持久独占的确依赖跟进，但 §9.5 已有任意管理员受控转派和超时提醒，不是永久无恢复路径，更不要求“另一名特定管理员”。补自动生成需要转派待办和替补提醒，拒绝自动夺权。 |
| AX-A3 实物证据不可验证 | 部分采纳 | V1.2 已要求目标、实际签收人、日期、凭证、扫码及账号，并非任意附件即可；附件与具体动作的统一绑定尚可加强。GPS、EXIF 也不能单独证明交付，不把采集这些信息作为信任保证。补证据关联及必要真实签收依据，不增加强制定位或见证角色。 |
| AX-A4 共享池无主 | 部分采纳 | §13.3 已有值班提醒人，§9.5 有处理时限；缺少跟进职责和替补触发的明确描述。补值班跟进与替补提醒，不引入审批认领、负载均衡或限定谁能批准。多人可见和有跟进人可以同时成立。 |
| AX-A5 100% 目标自相矛盾 | 不采纳其推导 | V1.2 §3.2 明确是目标，且公式就是外部抽样，不是声称能观察全体线下行为。30 笔有 1 笔漏记说明当前结果 96.7%，不是逻辑自相矛盾。只统计系统已有记录会变成自证，故保留分母并明确抽样、补录与真实责任变更边界。 |
| AX-A6 人工审批必须 Saga | 部分采纳 | 不能持有数据库事务等待人是正确的技术约束；原文同事务的对象是“建立待审批后续记录与转锁”，不是等待未来审批结束。建议强制 Saga 是无依据的架构扩张。§7.6 改写为分步短事务、持久业务锁、后来驳回的新恢复动作，不跨人工等待数据库事务。 |

原文把“全部流程的强度由最弱路径决定”“单确认覆盖从耗材到百万设备”等修辞当作已证事实不成立：不同业务路径可以有明确不同证据，且 V1 明确排除耗材。已完成物理销毁无法技术恢复是客观边界，不是增加审批人数就能消除的系统缺陷。

## 4. 深度审查 3.1–3.13 逐项裁决

| 编号 | 裁决 | 核验、真实场景与最小处置 |
|---|---|---|
| D-3.1 高价值报废分级 | 不采纳所提方案 | 价值字段、阈值及强制独立处置核验均超出已确认范围，且追加角色门槛违反用户决定。§8.9 已有批准、执行、待处置、凭证和受控冲正；§17.3 仅补批量清单及证据关联。企业将来有正式分级制度时另行确定范围，不提前实现。 |
| D-3.2 失联级联阻塞 | 部分采纳 | 12 张申请由一人占有时，自动抢办可能让已经交出的实物被重复分配，原文也已有受控转派。补 §9.5、AC-36：停用/明确无法处理及超时自动建去重提醒、通知替补，管理员决定转派。不能承诺管理员全体缺席仍自动完成实物交接。 |
| D-3.3 无权限下锁冲突无出口 | 采纳 | 数据裁剪后员工可能无法打开占用单，只有特权入口确实不够。§10.4 给受影响用户可执行的管理员协助入口，展示安全的状态解释，不泄露他人单号、附件或联系方式。AC-34。 |
| D-3.4 无法满足问责 | 部分采纳 | 原文已有原因、处理人和履历，“问责黑洞”过强；自由文本可改善。§8.4、AC-35 增加分类原因、当时库存摘要、对申请人和管理员可见及异议提醒。不加价值阈值、不让正常缺货重新审批，也不要求为库存事实手工截图。 |
| D-3.5 凭证绑定 | 部分采纳 | 最小关联规则值得统一；强制 GPS、EXIF、每条都扫码并不能可靠证明交付且会排除纸质凭证和标签损坏场景。§17.3 明确申请版本、资产、实际对象、业务时间、系统提交账号及接收时间、不可变附件摘要；摘要不充当真实性认证。AC-40。 |
| D-3.6 代确认必须独立见证 | 部分采纳 | 异常路径必须有实际签收依据，库管自写一句交付不能当凭证；这不等于必须新增独立角色、第二人审批或一律取得住院者在线授权。§9.3 已有真实目标及凭证、单管理员决定；补 §10.9、§17.3 的原单带入、依据核对与失效控制，保留不能交付时回库/改目标。 |
| D-3.7 期初未知成为盲点 | 部分采纳 | 待核验隔离是避免把不可信数据算成正式资产，不与统一台账矛盾；缺少持续跟进确会积压。新增 PRD-INIT-003，记录责任、账龄、缺项和下一次核实，默认 5 工作日提醒，不到期强制发布、删除或编造数据。复用初始化核验，不增一套正式盘点。AC-36。 |
| D-3.8 改成已记录业务证据率 | 不采纳所提指标 | 原分母从线下抽样，改成已记录业务会排除最需要发现的漏记。§3.2 改名抽样留痕率、保留 100% 目标并给 29/30 例子；同地受原责任人照管的短时共用无需新单，真实跨位置或责任转移不能口头豁免。AC-40。 |
| D-3.9 部门资产员查询个人资产 | 部分采纳 | §4.2 明确可查部门资产、§12.2 按使用组织划定范围，所以“必现查不到”未被证明；矩阵确漏了部门个人资产这一行，容易被实现者解释成无权。补 §12.1/12.2 的必要明细、代办选择和敏感字段边界。AC-39。 |
| D-3.10 遗失必须独立核销 | 部分采纳 | §8.9 已有遗失核销，不要求物理销毁；原借用保留至报废是用户已选 A 的责任保留规则，不等于财务欠账。独立提前核销会新增业务并与该决定冲突。不增加财务步骤，只在 §8.10 加跟进人、下次复核和继续保留/找回/现有报废出口。AC-36。 |
| D-3.11 离线 ID 丢失 | 采纳 | 同 ID 幂等并不能代替客户端可靠保存；V1.2 还有任务/资产结果去重，因此新 ID 不必然重复计数，但存储顺序未明确。§11.5 补先持久化再显示成功、崩溃续传原 ID及服务器同任务资产唯一计数；不同观察保留证据，不用指纹吞掉复盘。说明离线设备不能被服务端即时擦除。AC-38。 |
| D-3.12 初次绑定资料异常 | 采纳问题，限制实现 | 初次绑定就拿不到验证码的路径确实不足；无需管理员直接替绑。§11.1 复用人员维护和内部支持入口，核验后更正登记号码、作废旧验证码，员工仍自行短信验证；既有绑定不自动解除。AC-39。 |
| D-3.13 盘点录入规模 | 部分采纳 | §8.7 已有房间位置选择，只有必要照片，不是每件都重填全部字段；10 万是容量目标，不是一次盘点实际任务量。实际正常项仍应省操作：明确房间复用、逐件一次核实一致、差异展开、不确定可记录；不新增语音识别或自动判正常。AC-38。 |

## 5. ADV 用例及优先级如何处理

| 原用例 | 处置 | V1.3 中的实际预期 |
|---|---|---|
| ADV-01 高价报废要求独立核验 | 不按原预期并入 | 不采集价格阈值、不增加审批人；用 AC-09、AC-26、AC-40 验证既定流程、凭证和不可逆边界。 |
| ADV-02 失联后自动升级 | 改写吸收 | AC-36 自动产生跟进提醒，AC-30 由管理员受控转派；系统不保证无人处理时自行解除冻结。 |
| ADV-03 冲突有下一步 | 吸收 | AC-34 中无原单详情权限的受影响员工仍可通知管理员，不能泄漏无关数据。 |
| ADV-04 无法满足超阈值复核 | 改写吸收 | AC-35 原因与证据摘要、结果知情及异议入口，不再审批正常缺货。 |
| ADV-05 代确认强制独立见证 | 不按原预期并入 | AC-21、AC-35、AC-40 验证实际签收依据和单管理员决定，不强制新增见证角色。 |
| ADV-06 转换失败恢复 | 改写吸收 | 原 AC-23 保留单步原子性，新增 AC-37 区分已提交步骤和后来审批/拒绝，避免跨人长事务或反向抹除历史。 |
| ADV-07 待核验长期未决 | 改写吸收 | AC-36 显示责任、账龄和提醒，未解决行保持待核验而非到期强制发布。 |
| ADV-08 停用账号离线证据 | 已有覆盖并澄清 | 原 AC-15、AC-25 保留服务端立即拒绝；AC-38 澄清离线本地擦除能力与可靠持久化。 |
