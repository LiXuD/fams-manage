## 4. 关键修复亮点

1. **F8 是本轮最有价值的修复**：原实现账面与实际房间共用 `state.inventory`，切到 301 时账面也变 301，使位置差异无法被用户感知。现账面快照固定 302，实际房间独立，差异被正确显式化——直接守住 PRD §8.7"固定任务快照"原则。
2. **F1 修正方式优于原建议**：裁决未采用 REVIEW-D0.1 建议的区间算法（该算法会把终态步骤永远标为"未结束"），改为七情境显式映射，语义精确且限定在本原型示例。
3. **F4/F5 把"评审工具"与"产品界面"彻底分离**：冲突文案、离线情境、识别示例均只出现在 `#contextTools`（画布外），产品画布内不污染业务状态，符合 spec 的评审工具约定。
